# 安全说明：SSH 密钥库（@local/dsh-ssh-key-vault）

本文面向部署者与维护者，说明该插件的信任边界、保护能力、明确不保护的内容，以及推荐的使用方式。

> 结论先行：插件把私钥以 **0600 明文**保存在 DSH 数据目录；工作区授权是**逻辑授权**（页面与接口层的使用范围记录），**不是操作系统级隔离**；插件不提供私钥下载、加密、口令托管、SSH 连接测试或审计日志。

---

## 1. 范围与信任边界

### 1.1 组件

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| DSH Host 进程 | 运行 `dsh web` 的系统用户 | 提供 HTTP 路由、读写 `vault.json` 与 `keys/`、调用 `ssh-keygen` 校验 |
| 浏览器页面 | 设置 → SSH 密钥（同源 Web GUI） | 上传私钥、编辑主机、维护授权 |
| 数据目录 | `$DSH_HOME/ssh-key-vault/` | 明文私钥 + 元数据 + 授权关系 |
| 系统工具 | `ssh-keygen`（OpenSSH） | 校验私钥无口令并计算指纹 |

### 1.2 信任假设

**受信任：**

- 运行 DSH Web 的操作系统用户与宿主环境（内核、文件系统权限、`ssh-keygen` 二进制）；
- `$DSH_HOME` 所在磁盘与备份介质的管理者；
- 浏览器与 DSH Web 之间的同源会话（页面能访问，即视为已通过 DSH 自身的访问控制）。

**不受信任：**

- 工作区中的任意代码、Agent 生成的 shell 命令与文件内容；
- 其他系统用户（试图读取数据目录）；
- 任意跨源网页（试图借浏览器发起或读取请求）。

### 1.3 对手模型与结论

| 对手 | 能否获取私钥 | 说明 |
| --- | --- | --- |
| 本机其他系统用户 | 否（依赖文件权限） | 目录 0700、文件 0600，需同一用户或 root 才能读 |
| 同一系统用户的任意进程 / Agent | **能** | 可直接读取 `keys/` 下的文件；插件授权不阻止 |
| root / 宿主机管理员 | **能** | 可读任意文件，也可读进程内存 |
| 跨源网页 | 否 | 无 CORS，POST 校验同源 `Origin`；但无法防御同源页面被 XSS 控制 |
| 能登录 DSH Web 的远程用户 | 取决于 DSH 访问控制 | 插件不追加认证；见 §5.4 |
| 拿到磁盘/备份的人 | **能** | 明文存储，需靠磁盘加密与备份保护 |
| 拿到 `vault.json` 的人 | 部分 | 元数据、指纹、主机档案、授权关系；不含私钥正文，但主机信息本身敏感 |

## 2. 保护什么、不保护什么

### 2.1 保护

- 防止**其他系统用户**读取私钥（`0700` 目录 + `0600` 文件）；
- 防止私钥**离开本机**：接口不回传私钥、不提供下载、日志不打印私钥；
- 防止**误删仍被使用的密钥**：仍被主机引用时删除返回 409；
- 防止**跨站请求**操作密钥库：POST 校验 `Origin`、要求 JSON、限制 body 大小；
- 防止**数据损坏被静默覆盖**：`vault.json` 损坏时返回错误，不自动重建；
- 防止**路径穿越**：密钥文件只能落在 `keys/` 目录内，落盘前校验路径前缀。

### 2.2 不保护

- 不防御同一 OS 用户（含 Agent）直接读取密钥文件；
- 不加密私钥，不提供 KMS/硬件密钥库集成；
- 不防御 root、宿主机入侵、内存转储、swap、磁盘取证；
- 不提供多用户隔离、RBAC、审计日志、速率限制；
- 不校验主机可达性或远程主机真实身份（无 `known_hosts` 校验，因为不建立连接）；
- 不保护备份、快照、剪贴板或用户自己另存的私钥副本；
- 不防御同源 XSS：能执行同源脚本的攻击者可调用 API（但读不到私钥正文）。

## 3. 存储安全

### 3.1 明文与权限

```
$DSH_HOME/ssh-key-vault/            0700
├── vault.json                      0600   元数据、主机、授权
└── keys/                           0700
    └── <keyId>-<filename>          0600   私钥明文
```

- 私钥**不加密**：没有口令派生密钥、没有加密容器。任何能读取文件的人都能直接使用该私钥。
- 权限在创建时设置；若数据目录被移动到不支持 POSIX 权限的文件系统（如某些网络盘、FAT），权限保证失效，插件也无法补偿。
- 文件名经过白名单清洗（仅 `[A-Za-z0-9._-]`，去前导点，截断 96 字符）并带 `keyId` 前缀；读写前校验路径必须位于 `keys/` 内。

### 3.2 写入完整性

- `vault.json` 的所有写入通过同一 Promise 队列串行化，采用「临时文件 + `rename`」原子替换，避免并发写导致半截文件；
- 读取到损坏的 JSON 时返回 500 并保留现场，**不会**重置为空库；恢复方式见 §7；
- 密钥文件同样先写 `keys/` 内的临时文件（`0600`）再 `rename`，落盘后强制 `0600`；
- `keys/` 与 `vault.json` 的一致性由「先写密钥文件、后写元数据；删除时先删元数据、后删文件」的操作顺序维护，但两者之间仍存在极短的不一致窗口（进程崩溃时可能出现孤儿文件或缺失文件）。

### 3.3 内存与临时文件

- 上传时私钥正文会经过 Host 进程内存；校验阶段在 `os.tmpdir()` 下创建一次性目录（前缀 `dsh-ssh-key-vault-`）写入临时私钥（`0600`），校验结束后整目录删除。若进程崩溃，临时目录可能残留部分内容，建议将 `TMPDIR` 指向加密或受限目录。
- 私钥正文只写入临时文件，**不会**作为命令行参数传给 `ssh-keygen`；调用形式为 `ssh-keygen -y -P '' -f <临时文件>`，`-P ''` 用于断言私钥无口令。
- 浏览器端只在表单内持有文件内容，提交后不写入 `localStorage`/`sessionStorage`/IndexedDB。

## 4. 访问控制语义：逻辑授权，不是沙箱

`vault.json` 中的 `access` 只记录每个工作区被授权的主机：

- 有效主机 = 直接授权主机；
- 有效密钥 = 这些主机绑定的密钥。

授权主机即授权其密钥；不再单独授权密钥，也不会由密钥反向带出其他主机。这套记录只影响：

1. 设置页「工作区授权」中展示的已授权主机与随主机带出的密钥；
2. `GET /state` 返回的 `access`（仅 `hostIds`）；
3. 全局只读 Agent 工具 `ssh_targets`：按工作区返回被授权主机与密钥文件路径，不返回私钥正文，也不发起连接；
4. 后续可能使用这些记录的 UI/Agent 逻辑（本插件自身不发起 SSH 操作）。

`ssh_targets` 与 `GET /state` 一样不校验调用方身份：任何 Agent 都可以传任意工作区名，它只返回路径，不返回私钥正文。

它**不影响**文件系统权限，也**不校验调用方身份**：DSH 以单一 OS 用户运行，任何能调用 `/ssh-key-vault/*` 的同源请求都可以读写授权、上传或删除密钥。因此：

- 不要把「授权给某工作区」理解为「只有该工作区能读」；
- `POST /access/set` 是**覆盖式**写入：调用方可以一次性替换某工作区的全部主机授权（包括清空），也可以把任意主机授予任意工作区，且不会留下审计记录；
- 需要真正隔离时，必须使用**独立 OS 用户 + 独立 DSH_HOME + 文件权限/容器**，并让不同工作区运行在不同 OS 身份下；
- 撤销授权只改变记录，**无法收回**已经被复制出去的私钥。

## 5. 请求与传输安全

### 5.1 同源校验

POST 请求若带 `Origin` 头，必须满足其一：

- `Origin` 等于 WebServer 的公开 origin（`ctx.webServer.getOrigin()`）；
- `Origin` 的主机部分等于请求 `Host` 头（兼容反向代理）。

否则返回 403。这阻断跨站表单/`fetch` 直接写入；不带 `Origin` 的本机 `curl` 可通过（属于本机信任边界内的操作）。

### 5.2 内容类型与大小

- POST 必须是 `application/json`，否则 415（`unsupported_media_type`）；
- 请求体上限 256 KiB，超限 413（`body_too_large`）；上传内容上限 64 KiB（`key_too_large`，密钥文本通常仅数 KB）；
- 解析失败返回 400（`invalid_json`/`empty_body`/`invalid_body`）；
- 宿主机缺少可执行的 `ssh-keygen` 时，上传返回 503（`ssh_keygen_unavailable`），不会退化为不做校验的写入。

### 5.3 响应头与错误

- 所有响应带 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`；
- 不设置 `Access-Control-Allow-Origin`，浏览器默认阻止跨源读取；
- 错误统一 `{ ok: false, error: "中文提示", code: "stable_code" }`；`code` 用于程序判断，`500` 不返回堆栈、文件路径或内部异常文本；
- 响应只包含 ID、名称、文件名、SHA256 指纹、算法、位数、主机档案与授权关系，**不包含**私钥正文、绝对路径或 `relativePath`。

### 5.4 认证边界

插件依赖 DSH Web 自身的会话/访问控制，不额外提供登录、权限分级或速率限制：

- 能打开设置页的会话即可调用全部接口；
- 建议通过 `dsh-auth-cookie-guard` 等插件或反向代理认证限制访问；
- 不要把 Web GUI 直接暴露在公网；确需远程访问时使用 VPN/内网/反向代理 + 强认证。

### 5.5 日志

Host 侧日志只记录请求方法、错误 `code`、密钥 ID（文件清理失败时）等最小信息；不记录请求体、私钥内容、指纹以外的敏感字段。反向代理与 DSH 的访问日志可能记录请求路径与大小，但不会包含私钥（私钥在 POST body 中，日志默认不落 body）。

## 6. 生命周期与删除语义

| 操作 | 效果 | 可逆性 |
| --- | --- | --- |
| 上传私钥 | 写 `keys/` 文件（0600）并登记元数据；重复指纹 409 | 可删除 |
| 上传带口令/非法文件 | 校验失败即拒绝，不落盘、不残留元数据 | — |
| 重命名密钥/主机 | 只改元数据 | 可再改 |
| 改绑主机密钥 | 立即按新 `keyId` 重算有效访问 | 可再改 |
| 撤销工作区授权 | 从 `access` 移除；立即影响有效集合 | 可重新授权 |
| 删除主机 | 移除主机与所有工作区对该主机的授权；绑定密钥不再被其他主机使用时一并删除，否则保留 | 需重建 |
| 删除密钥 | 若仍被主机引用 → 409；否则删元数据与密钥文件（授权只引用主机） | **不可撤销** |

注意：

- 删除文件通常是「解除链接」，底层存储、快照与备份中仍可能保留旧内容，不能视为安全擦除；
- 撤销授权不是「密钥回收」，任何已复制出去的私钥副本仍然有效；
- 密钥轮换需要先在远程主机替换 `authorized_keys`，再删除旧密钥；本插件不代做远程操作。

## 7. 备份、恢复与数据损坏

- 备份包含**明文私钥**：备份介质的敏感级别应不低于 DSH 主机本身；建议加密备份、限制访问、定期清理；
- 恢复或迁移时，`vault.json` 与 `keys/` 必须来自同一份备份，且保持 `0700/0600` 权限；version 1 备份可直接恢复，首次读取会自动迁移为 host-only 授权，此后不要再用旧版插件写入；
- `vault.json` 损坏（JSON 解析失败、非法结构）时接口返回 500，**不会**自动重建空库，以免掩盖数据丢失；
- 恢复步骤：停止 DSH Web → 用备份覆盖 `$DSH_HOME/ssh-key-vault/` → 修复权限 → 启动并核对；
- 如果只有 `keys/` 没有 `vault.json`，密钥正文仍在，但名称、主机档案与授权丢失，需要按需重新登记或手工恢复元数据。

## 8. 推荐部署实践

1. **独立 OS 用户**：只允许一个专用用户运行 DSH，`$DSH_HOME` 设为 0700，限制 sudo/root 访问；
2. **磁盘加密**：全盘或数据盘加密（如 LUKS），防止离线读取与备份泄露；
3. **最小授权**：只给确实需要的工作区授权，定期复核「工作区授权」页；
4. **密钥专用**：为该密钥库生成专用密钥对，不与个人日常密钥、CI 密钥混用；在远程主机侧用 `authorized_keys` 的 `command=`/`from=` 限制用途；
5. **定期轮换**：怀疑泄露时立即在远程主机移除公钥，再在插件中删除私钥；
6. **限制入口**：Web GUI 不直接暴露公网；启用 DSH 认证插件或前置反向代理认证；
7. **备份加密**：备份与快照按密钥级别保护，避免把数据目录放进共享盘、公共云同步目录；
8. **审计**：如需要「谁在何时读取密钥」，在 OS 层用 `auditd`/`fanotify` 监控 `keys/` 访问；
9. **临时目录**：将 `TMPDIR` 指向加密目录，降低崩溃时临时私钥残留风险；
10. **谨慎卸载**：卸载插件不会删除数据；彻底清除需手动 `rm -rf`，并确认备份策略。

## 9. 已知限制

- 私钥**不加密**存储，无口令保护；
- 授权是**逻辑记录**，不构成沙箱或多租户隔离；
- 不支持带口令私钥、不支持私钥下载/导出、不支持托管口令；
- 不提供 SSH 连接测试、`known_hosts` 校验或远程命令执行；
- 只提供全局只读的 `ssh_targets` 查询工具，也不与 `dsh-push-deploy` 交互或迁移其密钥；
- 无审计日志、无速率限制、无细粒度 RBAC；
- 无「安全擦除」，删除后备份/快照仍可能含旧数据；
- 数据目录若位于不支持 POSIX 权限的文件系统，文件权限保护失效；
- 浏览器端视觉与交互未经像素级自动化验证，但接口与槽位注册可独立核验。

---

## 10. 报告安全问题

发现实现与本文描述不符（例如接口泄露私钥、路径穿越、越权写入）时：

1. 立即停止使用该插件并撤销相关主机上的公钥授权；
2. 保留 `$DSH_HOME/ssh-key-vault/` 现场（不要删除）；
3. 向插件维护者提供：复现步骤、DSH 版本、`vault.json` 的结构（**不要附私钥正文**）。
